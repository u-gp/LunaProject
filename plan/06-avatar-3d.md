# 06. 3D アバター（FBX / VRM）

## 1. 概要

FBX または VRM 形式の 3D モデルをウィンドウ上に表示し、AI の発話出力に応じてモデルを連動させる。

## 2. 機能要件

### F-AV-01 モデル読込

- ユーザーがローカルファイル（`.vrm` / `.fbx`）を選択して読み込める。
- 読込成功時、パスを設定に保存し次回起動で自動ロードする。
- 読込失敗時はエラー表示し、プレースホルダ（簡易メッシュまたは空）を出す。

### F-AV-02 ビューポート

- React 内のキャンバスで Three.js シーンを描画する。
- カメラはモデル全体が見える初期位置。簡易オービット（任意）を許可する。
- 背景は透過または単色設定可能（OBS キャプチャ用途を意識）。

### F-AV-03 発話連動（MVP）

最低限の連動:

| 連動 | VRM | FBX |
|------|-----|-----|
| 口パク（リップシンク） | `expression` / jaw 相当 | ブレンドシェイプまたは簡易スケール近似 |
| 待機モーション | idle アニメ or 首の微動 | idle クリップがあれば再生 |
| 発話開始ジェスチャ | 任意の短いモーション | 任意 |

MVP 合格ライン: **発話中に口が動くこと**。

### F-AV-04 リップシンク方式

優先順:

1. VOICEVOX の音素／タイミング情報が取れる場合はそれを利用。
2. 取れない場合は音声振幅（RMS）または発話時間ベースの簡易開閉。

### F-AV-05 フォーマット差分

- **VRM**: `@pixiv/three-vrm` を第一サポート。Humanoid / Expression を利用。
- **FBX**: `FBXLoader` で読込。ブレンドシェイプ命名が不明な場合は簡易フォールバック。

### F-AV-06 パフォーマンス

- 60fps 目標、不可時は 30fps へ自動低下してよい。
- ウィンドウ非表示時はレンダリングを停止または間引く。

## 3. API 契約（フロント / WebView 内）

```ts
interface AvatarController {
  loadModel(path: string, format: "vrm" | "fbx"): Promise<void>;
  playIdle(): void;
  startSpeaking(event: SpeakEvent): void;
  stopSpeaking(): void;
  dispose(): void;
}
```

## 4. 受け入れ条件

1. VRM を読み込み表示できる。
2. FBX を読み込み表示できる（アニメーションは可能な範囲）。
3. TTS 再生中に口パクが確認できる。
4. モデル未設定でもアプリ他機能が動作する。
